# ③ 32ビットのプロテクトモードと C 言語のカーネル

ここで CPU を32ビットモードに切り替え、C 言語で書いたカーネルを動かす。これ以降のプログラム(ドライバ、TCP、HTTP サーバー)は C で書いていく。

実行結果:

```
 hobby-os                                         ← 青い帯
Hello from C!

kmain()      is at 0x000080E0   (machine code, from 0x8000)
VRAM         is at 0x000B8000   (text screen memory)
boot_count   = 0x00000000   (.bss is zero-cleared)

32-bit protected mode + C kernel: OK               ← 緑の文字
```

## 全体の流れ

```
BIOS ─▶ boot.asm(0x7C00)        16ビット  ディスクからステージ2とカーネルを読み込む
         │
         ▼
       stage2.asm(0x7E00)       16ビット → 32ビットに切り替える
         │
         ▼
       kernel/entry.asm(0x8000) 32ビット  C を動かす準備(.bss を0で埋める)
         │ call
         ▼
       kernel/kernel.c kmain()  32ビット  ここから C の世界
```

ディスクイメージ(`build/os.img`)とメモリの対応:

| ディスク | 中身 | メモリ | 誰が読み込む |
|---|---|---|---|
| セクタ 0 | `boot.asm` | 0x7C00 | BIOS |
| セクタ 1 | `stage2.asm` | 0x7E00 | `boot.asm` |
| セクタ 2〜32 | カーネル(`entry.asm` + `kernel.c`) | 0x8000 | `boot.asm` |

## 1. なぜ32ビットモードに切り替えるのか

| | リアルモード(16ビット) | プロテクトモード(32ビット) |
|---|---|---|
| レジスタ | `ax`, `si` … | `eax`, `esi` … |
| 使えるメモリ | 1MB まで | 4GB まで |
| C 言語(gcc) | ほぼ使えない | 使える |
| BIOS の機能 | 使える | **使えない** |

Web サーバーにはネットワークの受信バッファや TCP の管理表など、たくさんのメモリと C 言語が必要。代わりに BIOS の機能は使えなくなるので、画面表示もネットワークも全部自分で書くことになる。

## 2. 切り替えの手順(`stage2.asm`)

```
① A20 ラインを有効にする     in/out 0x92      1MB より上を正しく使えるようにする
② 割り込みを止める           cli              切り替え中に邪魔されないように
③ GDT の場所を CPU に教える  lgdt             メモリの使い方の表
④ CR0 の最下位ビットを 1 に  mov cr0, eax     ここでプロテクトモードになる
⑤ ファージャンプ             jmp 0x08:...     CS を新しいセグメントに切り替える
⑥ 残りのセグメントレジスタとスタックを設定
⑦ カーネル(0x8000)へジャンプ
```

### GDT(グローバルディスクリプタテーブル)

プロテクトモードでは、セグメントレジスタ(`cs`, `ds` …)に入れる値は番地ではなく **「GDT という表の何番目を使うか」** になる。GDT の1行(8バイト)には開始番地、上限、コードかデータか、特権レベルなどが書いてある。

今回は一番単純な **フラットモデル**: 0番地から 4GB まで全部を、コード用とデータ用に1つずつ登録する。こうすると「番地 = そのままの番地」になり、セグメントを意識しなくてよくなる。

```
GDT
 0x00: 空(0番目は必ず空にする決まり)
 0x08: コード用  0〜4GB、実行・読み込み可   ← CODE_SEG(cs に入れる)
 0x10: データ用  0〜4GB、読み書き可         ← DATA_SEG(ds, ss などに入れる)
```

`10011010b` などのビットの意味:

| ビット | コード用 `10011010` | 意味 |
|---|---|---|
| 7 | 1 | このセグメントは存在する |
| 6-5 | 00 | 特権レベル0(一番強い = カーネル) |
| 4 | 1 | コードかデータのセグメント |
| 3 | 1 | コード(データ用は 0) |
| 1 | 1 | 読み込み可(データ用は「書き込み可」) |

`11001111b` の上位4ビットは「4KB 単位」「32ビット」、下位4ビットは上限の続き。上限 0xFFFFF × 4KB = 4GB。

### A20 ライン

昔の PC との互換性のため、起動直後は番地の20番目のビット(A20)が0に固定されていることがある。そのままだと 1MB を超える番地が0番地付近に巻き戻る。ポート `0x92` のビット1を立てて解除する(Fast A20)。

### ファージャンプが必要な理由

CR0 を書き換えた直後も `cs` にはリアルモードの値が残っていて、CPU はまだ16ビットとして命令を読んでいる。`jmp 0x08:番地` の形のジャンプで `cs` が GDT のコード用(32ビット)に切り替わり、ここから本当に32ビットで動き出す。

### 確かめ方

QEMU の画面で **Ctrl+Alt+2** → `info registers` → Enter(**Ctrl+Alt+1** で戻る)。

```
CS =0008 00000000 ffffffff 00cf9a00 DPL=0 CS32 [-R-]   ← GDT の 0x08 番、CS32 = 32ビット
CR0=00000011                                           ← 最下位ビットが 1 = プロテクトモード
```

## 3. C を動かすための準備

### 普通の C プログラムとの違い

普段の C プログラムは OS の上で動き、`printf` などの標準ライブラリや、`main` の前の準備を OS とライブラリがやってくれる。カーネルは **OS そのもの** なので、それが何もない。

| 普通のプログラム | このカーネル |
|---|---|
| `main()` から始まる | `kmain()`(名前は自由。`entry.asm` から呼ぶ) |
| `printf` で表示 | 画面のメモリに直接書く自作の `print` |
| OS が好きな番地に置いてくれる | **0x8000 番地に置くと自分で決める**(リンカスクリプト) |
| グローバル変数は OS が0にしてくれる | **自分で0にする**(`entry.asm`) |

### コンパイルの設定(`Makefile` の `CFLAGS`)

| オプション | 意味 |
|---|---|
| `-m32 -march=i686` | 32ビットの x86 向けに作る |
| `-ffreestanding` | 標準ライブラリがない環境向けに作る(`<stdint.h>` などの一部のヘッダーだけ使える) |
| `-fno-pie` | 決まった番地に置く前提で作る |
| `-mgeneral-regs-only` | SSE などの拡張命令を使わない。まだ有効にしていないので、使うと CPU が止まる |
| `-fno-stack-protector` | 標準ライブラリに頼るスタック保護機能を使わない |

### リンカスクリプト(`kernel/linker.ld`)

コンパイルしたプログラムを **メモリのどこに、どの順番で並べるか** の指示書。

```
0x8000  ┌─────────────────┐
        │ .text           │  機械語。先頭は必ず entry.asm の _start
        │                 │  (stage2.asm が 0x8000 にジャンプするため)
        ├─────────────────┤
        │ .rodata         │  書き換えない文字列など
        ├─────────────────┤
        │ .data           │  初期値のあるグローバル変数
        ├─────────────────┤
        │ .bss            │  初期値のないグローバル変数
        └─────────────────┘  ← __bss_start 〜 __bss_end
```

`nm -n build/kernel.elf` で、実際に各関数がどこに置かれたかを確認できる。画面の `kmain() is at 0x000080E0` はその値。

### `.bss` を0で埋める(`kernel/entry.asm`)

C では「初期値を書かないグローバル変数は0」という約束がある。普段は OS がやってくれるが、ここでは `entry.asm` が `rep stosb` で `__bss_start` 〜 `__bss_end` を0で埋めてから `kmain` を呼ぶ。画面の `boot_count = 0x00000000` は、それができている確認。

## 4. 文字の表示(`kernel/kernel.c`)

BIOS が使えないので、画面のメモリ(**VRAM**、`0xB8000` 番地から)に直接書く。テキスト画面は 80文字 × 25行で、1文字は2バイト。

```
番地     0xB8000   0xB8001   0xB8002   0xB8003 ...
中身     'H'       色        'e'       色
         └── 1文字目 ──┘     └── 2文字目 ──┘
```

C では `uint16_t` の配列として扱うと分かりやすい: `vga[行 * 80 + 列] = 色 << 8 | 文字`。

色の1バイトは上位4ビットが背景、下位4ビットが文字の色(0 黒、1 青、2 緑、7 灰、A 明るい緑、F 白 …)。`0x1F` は青地に白。

`volatile` を付けているのは、「このメモリへの書き込みには意味がある(画面に出る)ので、省略しないで」とコンパイラに伝えるため。付けないと、最適化で書き込みが消されることがある。

画面の一番下まで来たら、全体を1行上にずらす(スクロール)処理も自分で書いている。

## 補足

- 画面の左下で点滅しているカーソルは BIOS 時代の位置のまま。カーソルの移動は VGA のポートを操作する必要があり、今は省略している。
- カーネルの大きさは今 約1KB。読み込める上限は31セクタ(15.5KB)で、超えると `make` がエラーで知らせる。そのときは `Makefile` の `LOAD_SECTORS` を増やす。
