# ④ 割り込み: タイマーとキーボード

ここで **割り込み** のしくみを作る。装置(タイマー、キーボード、そして後のネットワークカード)が「何か起きた」と CPU に知らせる方法。

実行結果(キーを打つとそのまま表示され、右上の時間が1秒ごとに進む):

```
 hobby-os                                                      uptime 00:00:06
PIC      : remap IRQ 0-15 to interrupt 32-47 ... ok
IDT      : register interrupt handlers 0-47 ... ok
Timer    : IRQ0, 100 Hz ... ok
Keyboard : IRQ1 ... ok

Interrupts enabled. Type something!

> hello os
> Hi!
> _
```

## 1. なぜ割り込みが必要か

Web サーバーは「パケットがいつ届くか分からない」ものを相手にする。方法は2つある。

| 方法 | やり方 | 例え |
|---|---|---|
| ポーリング | CPU が「届いた?」と何度も見に行く | 郵便受けを1分ごとに見に行く |
| **割り込み** | 届いたら装置が CPU に知らせる | 郵便が来たらチャイムが鳴る |

ポーリングは CPU を無駄に使い続ける。割り込みなら、何もない間は CPU を休ませ(`hlt`)、何か起きたときだけ動ける。

## 2. 全体のしくみ

```
 タイマー ─IRQ0─┐
 キーボード─IRQ1─┤              割り込み番号        IDT(番号 → 飛び先の表)
 (NIC など)─IRQn─┴─▶ PIC ─────────▶ CPU ──────▶  32 → isr32 ─┐
                   (IRQ を番号に                  33 → isr33 ─┤
                    変換して伝える)                ...         │
                                                               ▼
                    isr.asm(入り口)  レジスタを全部保存して C を呼ぶ
                          │
                          ▼
                    idt.c isr_handler()  番号を見て振り分け
                          ├─ 0〜31 : CPU の例外 → 赤で表示して止まる
                          └─ 32〜47: 装置 → 登録された関数を呼ぶ
                                       ├─ IRQ0 → timer.c    timer_irq()
                                       └─ IRQ1 → keyboard.c keyboard_irq()
                          │
                          ▼
                    PIC に「終わった(EOI)」と伝える → iret で元の処理に戻る
```

割り込みが来ると、CPU は **今やっていることを中断して** 割り込みの処理に飛び、終わったら **中断したところから再開** する。中断された側(`kmain` のループ)は、割り込まれたことに気づかない。

## 3. 部品ごとの説明

### PIC(`pic.c`): 装置からの信号の取りまとめ役

装置からの信号(IRQ = Interrupt Request)は、いったん PIC に集まる。PIC は2つあり、マスターが IRQ 0〜7、スレーブが IRQ 8〜15 を受け持つ。

| IRQ | 装置 |
|---|---|
| 0 | タイマー(PIT) |
| 1 | キーボード |
| 2 | スレーブ PIC へのつなぎ |
| 9〜11 あたり | ネットワークカードなど(⑥で使う) |

**番号をずらす(リマップ)**: 起動直後の PIC は IRQ 0〜7 を割り込み番号 8〜15 として CPU に伝える。ところが 8〜15 は CPU の例外(8 = ダブルフォルト、13 = 一般保護例外 …)と重なっている。区別できるように、IRQ 0〜15 を 32〜47 にずらす。

**マスク**: 使わない IRQ は止めておく。最初は全部止め、`irq_register()` で登録したものだけ開ける。

**EOI(End Of Interrupt)**: 処理が終わったら PIC に `0x20` を送って知らせる。**忘れると PIC は次の割り込みを送ってこない**。

### IDT(`idt.c`): 割り込み番号 → 飛び先の表

③の GDT と同じく、CPU に表の場所を `lidt` 命令で教える。1行8バイトで「飛び先の番地」と「どのコードセグメントで動くか(0x08)」などが書いてある。

| 番号 | 中身 |
|---|---|
| 0〜31 | CPU の例外。0 = 0で割った、6 = 存在しない命令、13 = 一般保護例外、14 = ページフォルト … |
| 32〜47 | 装置からの割り込み(IRQ 0〜15) |

### 入り口(`isr.asm`): C を安全に呼ぶための準備

割り込みは、プログラムのどこで起きるか分からない。割り込まれた側のレジスタの値を壊すと、戻ったあとに処理がおかしくなる。そこで:

1. 割り込み番号をスタックに積む(どの割り込みか C に伝えるため)
2. `pusha` で全レジスタを保存する
3. C の `isr_handler()` を呼ぶ
4. `popa` で全レジスタを戻す
5. `iret` で中断したところに戻る

スタックには次の順で積まれていて、C 側では `struct regs`(`idt.h`)として読める。

```
低い番地  edi esi ebp esp ebx edx ecx eax   ← pusha
          割り込み番号  エラーコード         ← isrN
高い番地  eip cs eflags                      ← CPU が自動で積む(戻り先)
```

例外のうちいくつか(8, 10〜14 番など)は CPU がエラーコードを自動で積む。形をそろえるため、それ以外ではダミーの 0 を積んでいる(`ISR_NOERR` と `ISR_ERR` の違い)。

### タイマー(`timer.c`): OS の時計

PIT は 1,193,182 Hz で数を数えている部品。「11,931 回数えるごとに IRQ0」と設定すると、1秒に100回(10ミリ秒ごと)割り込みが来る。割り込みのたびに `ticks` を1増やすだけ。

`ticks / 100` が起動してからの秒数になる。右上の `uptime` はこれを表示している。⑧の TCP では「1秒待っても返事がなければ送り直す」といった処理にこの時計を使う。

### キーボード(`keyboard.c`): スキャンコードを文字に

キーを押す・離すたびに IRQ1 が来る。ポート `0x60` を読むと **スキャンコード** が取れる。

| 操作 | スキャンコード |
|---|---|
| A を押す | `0x1E` |
| A を離す | `0x9E`(押したとき + `0x80`) |
| 左 Shift を押す | `0x2A` |

スキャンコードは「キーボード上のどの位置のキーか」を表す番号で、文字ではない。対応表(`keymap`)で文字に変換する。Shift が押されている間は別の表(`keymap_shift`)を使う。

> 対応表は US 配列。日本語キーボードでは、英字・数字・Enter・Backspace は同じだが、記号の位置がずれる(例: `Shift+2` が `"` ではなく `@` になる)。

### I/O ポート(`io.h`)

PIC、PIT、キーボードとは **I/O ポート** という番号付きの窓口でやりとりする。メモリとは別の空間で、`in` / `out` という専用の命令を使う。C には書き方がないので、インラインアセンブリ(`__asm__`)で呼んでいる。

| ポート | 装置 |
|---|---|
| `0x20`, `0x21` | マスター PIC |
| `0xA0`, `0xA1` | スレーブ PIC |
| `0x40`, `0x43` | PIT(タイマー) |
| `0x60` | キーボード |
| `0x3D4`, `0x3D5` | VGA(点滅カーソルの位置) |

## 4. 割り込みの中では「短く」

`keyboard_irq()` は文字を **リングバッファに入れるだけ** で、画面への表示は `kmain()` のループでやっている。

```
keyboard_irq()(割り込みの中)          kmain() のループ
   スキャンコード → 文字              ┌──────────────────────────┐
         │                            │ バッファから文字を取り出す │
         ▼                            │ → 画面に表示              │
   ┌─┬─┬─┬─┬─┬─┐                   │ 1秒たったら時間を更新     │
   │h│e│l│l│o│ │ ─────────────────▶ │ hlt(次の割り込みまで休む)│
   └─┴─┴─┴─┴─┴─┘ リングバッファ      └──────────────────────────┘
   head(書く位置)  tail(読む位置)
```

理由:
- 割り込みの処理中は、他の割り込みが待たされる。長いと、キーの取りこぼしやタイマーの遅れが起きる
- 割り込みはどこで起きるか分からない。`kmain` が画面に書いている途中で、割り込みの中からも画面に書くと、表示が混ざって壊れる

**ネットワークカードの受信も同じ形にする予定**: 割り込みでは受け取ったパケットを置いておくだけにして、TCP や HTTP の処理はメインのループでやる。

## 5. 例外の表示

CPU の例外(0〜31番)が起きると、赤い帯で内容を表示して止まる。例えば0で割ると:

```
 EXCEPTION: Divide by zero (#0) at EIP=0x00008276 error=0x00000000
```

`EIP` は例外が起きた命令の番地。`nm -n build/kernel.elf` の一覧と見比べると、どの関数の中で起きたか分かる。今後バグで止まったときの手がかりになる。

> 小話: 動作確認で `1 / z`(z = 0)を書いたら、例外が起きなかった。gcc が「1 を割る」場合だけ、割り算を使わない比較の命令に置き換えていたため。`7 / z` にしたら `idiv` 命令が使われ、例外が起きた。コンパイラの最適化は、こういうところにも効いている。

## 補足

- カーネルは約4KB になった。上限は 15.5KB(`LOAD_SECTORS` = 32)
- `Makefile` は `kernel/` の中の `.c` と `.asm` を自動で全部ビルドするようにした。ファイルを増やしても `Makefile` を書き換えなくてよい
