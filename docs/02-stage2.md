# ② 512バイトの壁を越える

BIOS が読み込んでくれるのはブートセクタの512バイトだけ。ゲームはもちろん、32ビットモードへの切り替えすら収まらない。そこでプログラムを2段構えにする。

## しくみ

```
ディスク(build/os.img)                    メモリ
┌───────────────────┐
│ セクタ0: boot.asm  │ ──BIOSが読む──▶ 0x7C00  ステージ1
├───────────────────┤
│ セクタ1〜32:      │ ──ステージ1が──▶ 0x7E00  ステージ2
│   stage2.asm      │    int 0x13 で読む
└───────────────────┘
```

1. BIOS がセクタ0(ステージ1)を 0x7C00 に読み込んで実行する
2. ステージ1は、BIOS のディスク読み込み機能でセクタ1〜32(ステージ2、16KB)を 0x7E00 に読み込む
3. ステージ1が 0x7E00 にジャンプし、ステージ2が動き出す

実行結果:

```
Booting from Hard Disk...
Stage 1: loading stage 2...
Stage 2: Hello from beyond the 512-byte boot sector!
Stage 2: last sector loaded OK.
```

## ポイント

### 起動ディスクの番号は `dl` で渡される

BIOS はジャンプするとき、起動したディスクの番号(ハードディスクなら通常 `0x80`)を `dl` レジスタに入れておいてくれる。ディスクを読むときにこの番号が必要なので、最初に `boot_drive` に保存しておく。

### ディスクの読み込み: `int 0x13`, `ah=0x42`

「何セクタ目から、何セクタを、メモリのどこへ」を **DAP(ディスクアドレスパケット)** という16バイトの表に書き、`si` でその場所を教えて呼び出す。

```nasm
dap:
    db 0x10             ; この表の大きさ(16バイト)
    db 0                ; 予約(常に0)
    dw STAGE2_SECTORS   ; 読み込むセクタ数
    dw STAGE2_ADDR      ; 読み込み先の番地(オフセット)
    dw 0                ; 読み込み先の番地(セグメント)
    dq 1                ; ディスクの何セクタ目から読むか(LBA)
```

セクタの位置はディスクの先頭から数えた通し番号(**LBA**)で指定する。昔ながらの `ah=0x02` はシリンダ・ヘッド・セクタ(CHS)という3つの数字で指定する必要があり面倒なので、拡張機能の `ah=0x42` を使っている。

失敗するとキャリーフラグが立つので、`jc disk_error` でエラーメッセージを出して止める。ステージ2を含まないイメージ(`build/boot.bin` だけ)で起動すると、`Disk read error!` と表示されることを確認済み。

### 全部読み込めたかの確認

`stage2.asm` の**最後のセクタの末尾**に確認用の文字列を置き、それを表示している。`last sector loaded OK.` が出れば、32セクタすべてが正しく読み込まれている。

### 大きさの管理

ステージ2の大きさ(`STAGE2_SECTORS`)は `Makefile` で1か所だけ決め、`-D` で `boot.asm` と `stage2.asm` の両方に渡している。

- `stage2.asm` は `times` で末尾まで0埋めされるので、`build/stage2.bin` は常にちょうど `STAGE2_SECTORS × 512` バイトになる
- 中身が大きくなって収まらなくなると `times` が負になり、nasm がエラーを出す。そのときは `Makefile` の `STAGE2_SECTORS` を増やす
- 0x7E00 から使えるのは約480KB(`0x9FC00` まで)。BIOS によっては1回に読めるのは127セクタまで

### 共通ルーチン

文字列表示は `print16.inc` にまとめ、`%include` で両方から使っている。`pusha` / `popa` でレジスタを保存・復元するので、呼び出し元のレジスタの値を壊さない。
