## 1. なぜメモリ管理が必要か

ここまでの変数は全部「最初から大きさが決まっているもの」だった(グローバル変数、関数の中の変数)。でも Web サーバーでは:

| 必要になるもの | 大きさ | いくつ? |
|---|---|---|
| 届いたパケット | 60〜1514 バイト | 届いた数だけ |
| TCP の接続の情報 | 数十〜数百バイト | 同時につないでいる数だけ |
| HTTP の応答 | ページによる | リクエストの数だけ |

どれも **いつ、いくつ必要になるか前もって分からない**。全部を最大の数だけ用意しておくと、メモリがいくらあっても足りない。そこで「必要になったら借りて、終わったら返す」ようにする。


## 3. ① メモリの地図(E820)

### なぜ地図が要るのか

メモリは 0 番地から最後まで全部が使えるわけではない。BIOS が使っている場所、装置がつながっている場所(画面の `0xB8000` もその1つ)、壊れている場所がある。**どこが使ってよいかを知っているのは BIOS だけ** なので、聞くしかない。

### 聞き方(`stage2.asm`)

BIOS の `int 0x15`(`eax = 0xE820`)を呼ぶと、1回につき1項目ずつ返してくれる。

| レジスタ | 渡すもの | 返ってくるもの |
|---|---|---|
| `eax` | `0xE820`(機能の番号) | `'SMAP'`(合言葉。違えば非対応) |
| `ebx` | 「続きはどこから」(最初は 0) | 次に渡す値。**0 なら最後の項目** |
| `ecx` | 書き込み先の大きさ(24) | 実際に書いた大きさ |
| `edx` | `'SMAP'`(合言葉) | |
| `es:di` | 書き込み先の番地 | |

これを `ebx` が 0 になるまでくり返し、結果を `0x1000` 番地に並べておく。

```
0x1000: 項目の数
0x1004: ┌ 開始番地(8バイト) │ 大きさ(8バイト) │ 種類(4) │ 拡張属性(4) ┐ 項目0
0x101C: └ …                                                           ┘ 項目1
```

**プロテクトモードに入ると BIOS は使えなくなる**(BIOS は16ビットのリアルモード用のプログラムだから)。だから ③ で作った切り替えの前に、ステージ2で聞いておく。カーネル(`memmap.h`)は置いてある表を読むだけ。

### 地図の読み方

上の実行結果(QEMU、メモリ 128MB)を図にすると:

```
0x00000000 ┌──────────────────────┐
           │ usable (639KB)       │ ← カーネル(0x8000〜)とスタック(〜0x90000)もここ
0x0009FC00 ├──────────────────────┤
           │ reserved             │ ← BIOS の作業場所(EBDA)
0x000A0000 ├ - - (地図にない) - - ┤ ← 画面(0xB8000)など。地図に載っていない所も使ってはいけない
0x000F0000 ├──────────────────────┤
           │ reserved             │ ← BIOS のプログラム本体
0x00100000 ├──────────────────────┤ 1MB
           │ usable (約126MB)     │ ← ここを貸し出す
0x07FE0000 ├──────────────────────┤
           │ reserved             │
0x08000000 └──────────────────────┘ 128MB
```

番地や大きさが64ビットなのは、4GB より上のメモリも表せるようにするため。QEMU を `-m 5120`(5GB)で起動すると、`0x00000001_00000000` から先に usable が出てくる。このOSは32ビットなので、4GB より上は使わずに捨てている。

## 4. ② ページ単位の管理(`pmm.c`)

### ページとは

メモリを **4KB(4096バイト)ずつ** に区切ったもの。1バイト単位で管理すると記録が大きくなりすぎるので、ある程度まとめて扱う。4KB なのは、x86 の CPU がメモリを守るしくみ(ページング)も 4KB 単位で動くから。

```
番地       0x00000  0x01000  0x02000  0x03000  …
ページ番号    0        1        2        3     …
```

番地 ÷ 4096 = ページ番号。4096 = 2^12 なので、**番地を12ビット右にずらすとページ番号** になる(`addr >> 12`)。

### ビットマップ: 1ページを1ビットで記録する

```
ページ番号: 256 257 258 259 260 261 262 263 …
ビット    :  1   1   0   0   0   1   0   0  …     1 = 使用中 / 0 = 空き
                     └─空き─┘       └空き┘
```

4GB ÷ 4KB = 1,048,576 ページ → 1,048,576 ビット = **128KB**。これでメモリ全体の様子が分かる。

| 操作 | やること |
|---|---|
| `pmm_init()` | 全部「使用中」にしてから、地図で usable の所だけ「空き」にする |
| `pmm_alloc(n)` | 前から順に、0 が n 個続いている所を探して 1 にする |
| `pmm_free(addr, n)` | そこを 0 に戻す |

**「全部使用中から始める」のがポイント**。逆(全部空きから始めて、使えない所を埋める)にすると、地図に載っていない場所(画面の `0xB8000` など)を貸してしまうおそれがある。安全な側に倒しておく。

### 1MB より下は貸さない

1MB より下にも usable はあるが、貸し出さない。ここにはすでに大事なものが置いてある。

| 番地 | 中身 |
|---|---|
| `0x1000` | メモリの地図 |
| `0x7C00`〜 | ステージ1・2(もう使わないが) |
| `0x8000`〜 | **カーネル本体と、このビットマップ自身**(`.bss` にある) |
| 〜`0x90000` | **スタック**(下に向かって伸びる) |
| `0xA0000`〜 | 画面や BIOS |

うっかり貸すと、借りた人が書き込んだ瞬間にカーネル自身やスタックが壊れる。

### 番地 0 を「失敗」の印に使う

`pmm_alloc` は借りられなかったとき 0 を返す。0 番地のページは絶対に貸さない(1MB より下だから)ので、0 が返ってきたら「失敗」と決められる。C の `malloc` が失敗すると `NULL`(0)を返すのと同じ考え方。

## 5. ③ ヒープ(`heap.c`): kmalloc / kfree

### なぜページの上にもう1段必要か

パケット1つは最大 1.5KB、TCP の接続情報は数十バイト。それぞれに 4KB のページを丸ごと使うと、大半が無駄になる。そこでページを借りてきて、**中を細かく切り分けて貸す**。

### 区画と見出し

ヒープの中は「見出し(16バイト) + 中身」の区画が、番地の順にすき間なく並んでいる。

```
┌──────────┬──────────┬──────────┬────────┬──────────┬──────────────┐
│ 見出し   │ 中身     │ 見出し   │ 中身   │ 見出し   │ 中身         │
│ USED 112 │ 貸出中   │ FREE 32  │ 空き   │ USED 2000│ 貸出中       │
└──────────┴──────────┴──────────┴────────┴──────────┴──────────────┘
  ↑ kmalloc が返すのは、見出しの直後(中身の先頭)の番地
```

見出しの中身:

| 項目 | 意味 |
|---|---|
| `size` | 中身の大きさ |
| `magic` | `USED`(貸出中)か `FREE`(空き)。文字として読める値にしてある |
| `prev` / `next` | 番地が1つ前・1つ後の区画 |

`kfree(p)` には番地しか渡されないのに大きさが分かるのは、**`p` の16バイト手前に見出しがある** から。

### kmalloc(n)

1. n を16の倍数に切り上げる(`kmalloc(100)` → 112)
2. 前から順に、`FREE` で n 以上の区画を探す(**ファーストフィット**)
3. 見つかった区画が大きすぎたら、後ろの余りを新しい `FREE` 区画として切り分ける(**分割**)
4. どこにもなければ、pmm からページを借り足して(最低16ページ = 64KB)、もう1回探す

```
kmalloc(100) の前:  │FREE 65520                                         │
kmalloc(100) の後:  │USED 112│FREE 65392                                │
                     ^^^^^^^^ 切り分けた
```

### kfree(p) と「くっつける」

返された区画を `FREE` に戻すだけだと、空きがどんどん細切れになる(**断片化**)。合計では足りているのに、大きいものが借りられなくなる。

```
くっつけないと: │FREE 112│FREE 2000│FREE 32│  → 2100 バイトを借りられない!
くっつけると  : │FREE 2176                 │  → 借りられる
```

そこで返すときに、**すぐ後ろとすぐ前の区画も `FREE` なら1つにまとめる**(**結合**)。`prev` を持っているのは、前の区画をすぐ見つけるため。

### 起動時のテスト

`kernel.c` の `heap_self_test()` で、毎回起動時に確かめている。

1. 100、2000、30 バイトを借りる → 番地が16の倍数で、重なっていないか
2. 2000 の方を返して 1000 を借りる → **同じ場所が再利用されるか**
3. 全部返す → **くっついて、空き区画1つ(65520 バイト)に戻るか**

`mem` の `Heap : 0 used / 65520 bytes, 1 blocks (1 free)` は、テストの後にきれいに元に戻ったことを示している(64KB = 65536 から見出し16バイトを引いた値)。

### バグの見つけ方

`kfree` は見出しの `magic` が `USED` でなければ、赤字で `kfree: bad pointer` と表示して何もしない。次のバグを見つけるため:
- **二重解放**: 同じものを2回返した(2回目は `FREE` になっている)
- kmalloc で借りていない番地を返した
- 借りた大きさより多く書き込んで、**次の区画の見出しを壊した**

## 6. 小さなコマンドライン

確かめやすいように、キーボードから1行ずつ読んでコマンドを実行するようにした(`kernel.c` の `kmain` と `run_command`)。

| コマンド | やること |
|---|---|
| `help` | コマンドの一覧 |
| `mem` | メモリの地図、ページの空き、ヒープの様子 |
| `clear` | 画面を消す |

Backspace は打った文字だけを消し、プロンプトの `> ` は消さないようにした。今後 `ping` を打つなど、コマンドを足していく土台になる。

## 7. `memset` と `memcpy`(`string.c`)

標準ライブラリがないので自分で用意した。gcc は構造体のコピーなどで、書いていないのに `memset` や `memcpy` を呼ぶことがあるので、この名前で置いておく必要がある。

C のループで書かずに、x86 の `rep stosb`(埋める)/ `rep movsb`(写す)命令を使っている。ループで書くと、gcc が「これは memset だ」と見抜いて `memset` の呼び出しに置き換え、**memset が自分自身を永遠に呼び続ける** ことがあるため。

## 補足

- カーネルは約7.5KB になった。上限は 15.5KB(`LOAD_SECTORS` = 32)。ビットマップ(128KB)は `.bss` なので、ディスク上の大きさには入らない
- ヒープは借りたページを pmm に返さない(一度大きくなったら縮まない)。今の使い方では困らないので、簡単な方を選んだ
- 本物の OS はさらに **ページング** で「プログラムごとに別々の番地の世界」を作り、他のプログラムのメモリを壊せないようにしている。このOSはカーネルだけが動くので、今は使っていない(必要になったら足す)
