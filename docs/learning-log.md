## ① 起動 — [01-boot.md](01-boot.md)

**分かったこと**
- 電源を入れると BIOS が動き、ディスクの先頭512バイト(ブートセクタ)を `0x7C00` 番地に読み込んで実行する
- ブートセクタの最後の2バイトが `55 AA` でないと、BIOS は「起動できない」と判断する
- 起動直後の CPU は、1978年の 8086 との互換のため **16ビットのリアルモード** で動いている
- BIOS は文字表示(`int 0x10`)やディスク読み込み(`int 0x13`)を手伝ってくれるが、リアルモードでしか使えない
- やることがなくなったら `hlt` で止める。止めないと、CPU はデータを命令だと思って実行し暴走する

**キーワード**: BIOS、ブートセクタ、`0x7C00`、`55 AA`、リアルモード、`[org]`、`hlt`

## ② 512バイトの壁を越える — [02-stage2.md](02-stage2.md)

**分かったこと**
- 512バイトでは何もできないので、**2段構え** にする。ステージ1はディスクの続きを読み込んでジャンプするだけ
- ディスクの読み込みは `int 0x13`(`ah=0x42`)。「どこから・何セクタ・メモリのどこへ」を DAP という表に書いて渡す
- セクタの位置は先頭からの通し番号(LBA)で指定する
- BIOS は起動したディスクの番号を `dl` で渡してくれる

**キーワード**: ステージ1 / ステージ2、`int 0x13`、DAP、LBA、セクタ

## ③ 32ビットモードと C 言語 — [03-protected-mode.md](03-protected-mode.md)

**分かったこと**
- 4GB のメモリと C 言語を使うため、**プロテクトモード** に切り替える。代わりに BIOS は使えなくなる
- 切り替えの手順: A20 を有効に → 割り込みを止める → GDT を教える(`lgdt`)→ CR0 の PE ビットを 1 に → ファージャンプ
- **GDT** は「メモリをどう使うか」を CPU に教える表
- OS を作るときの C には、標準ライブラリも `main` を呼んでくれる人もいない。`entry.asm` が `.bss` を0で埋めてから `kmain()` を呼ぶ
- リンカスクリプトで「カーネルを `0x8000` 番地から並べる」と指示する
- 画面には VRAM(`0xB8000`)に直接書く。1文字は「文字 + 色」の2バイト。`volatile` で書き込みを最適化で消させない

**キーワード**: プロテクトモード、GDT、CR0、ファージャンプ、A20、`-ffreestanding`、リンカスクリプト、`.bss`、VRAM、`volatile`

## ④ 割り込み — [04-interrupts.md](04-interrupts.md)

**分かったこと**
- 「いつ来るか分からないもの」を待つ方法は、ポーリング(何度も見に行く)と **割り込み**(来たら知らせてもらう)がある。割り込みなら待つ間は CPU を休ませられる
- 装置の信号(IRQ)は **PIC** に集まり、PIC が CPU に割り込み番号として伝える。CPU の例外(0〜31)と重ならないよう、IRQ 0〜15 を 32〜47 にずらす(リマップ)
- **IDT** は「割り込み番号 → 飛び先」の表。入り口(`isr.asm`)でレジスタを全部保存してから C を呼び、`iret` で戻る
- 処理が終わったら PIC に **EOI** を送る。忘れると次の割り込みが来ない
- **割り込みの中は短く**: キーボードは文字をリングバッファに入れるだけで、表示はメインのループでする(ネットワークの受信も同じ形にする予定)
- タイマー(PIT)を 100Hz にして、OS の時計にした
- CPU の例外は赤字で表示して止まる。`EIP` と `nm -n build/kernel.elf` を見比べると、どこで起きたか分かる

**キーワード**: 割り込み、IRQ、PIC、リマップ、マスク、EOI、IDT、ISR、`iret`、例外、PIT、スキャンコード、リングバッファ、`volatile`

## ⑤ メモリ管理 — [05-memory.md](05-memory.md)

**分かったこと**
- パケットや TCP の接続のように、**いつ・いくつ要るか分からないもの** のために「借りて、返す」しくみが要る
- 3段構えになっている
  1. **メモリの地図(E820)**: どこが使ってよいかは BIOS しか知らない。プロテクトモードに入る前にステージ2で聞いておく
  2. **ページの管理(pmm)**: メモリを 4KB のページに区切り、1ページを1ビットで記録する(ビットマップ)。番地を12ビット右にずらすとページ番号
  3. **ヒープ(kmalloc / kfree)**: ページを「見出し + 中身」の区画に切り分けて貸す。返されたら隣の空き区画とくっつけて、断片化を防ぐ
- 安全な側に倒す設計: ビットマップは「全部使用中」から始め、使ってよい所だけ空ける。1MB より下(カーネル、スタック、BIOS)は貸さない
- 番地 0 は絶対に貸さないので、「失敗」の印に使える(`malloc` の `NULL` と同じ考え方)
- `kfree` に番地しか渡さなくても大きさが分かるのは、16バイト手前に見出しがあるから
- gcc はループを勝手に `memset` 呼び出しに置き換えることがある。`memset` 自身はループで書かず、`rep stosb` を使う

**キーワード**: E820、ページ、ビットマップ、ファーストフィット、分割、結合、断片化、見出し、二重解放

## 全体を通して分かったこと

- **「誰がやってくれていたか」を自分でやる**: 普段の C では OS がやってくれていたこと(`.bss` を0にする、`malloc`、画面への表示)を、全部自分で用意する必要がある
- **BIOS に頼めるのはリアルモードの間だけ**: ディスクの読み込みもメモリの地図も、32ビットに切り替える前に済ませておく
- **番地の取り決めが大事**: `0x1000`(メモリの地図)、`0x7C00`(ステージ1)、`0x7E00`(ステージ2)、`0x8000`(カーネル)、`0x90000`(スタック)、`0xB8000`(画面)。どこに何を置くかを決めて、ぶつからないようにする
- **作ったら QEMU で確かめる**: 起動時のテスト(`heap_self_test`)や確認用の表示(`last sector loaded OK.`、`mem`)を入れておくと、壊れたときにすぐ分かる
