## ① 起動 — [01-boot.md](01-boot.md)

**分かったこと**
- 電源を入れると BIOS が動き、ディスクの先頭512バイト(ブートセクタ)を `0x7C00` 番地に読み込んで実行する
- ブートセクタの最後の2バイトが `55 AA` でないと、BIOS は「起動できない」と判断する
- 起動直後の CPU は、1978年の 8086 との互換のため **16ビットのリアルモード** で動いている
- BIOS は文字表示(`int 0x10`)やディスク読み込み(`int 0x13`)を手伝ってくれるが、リアルモードでしか使えない
- やることがなくなったら `hlt` で止める。止めないと、CPU はデータを命令だと思って実行し暴走する

**キーワード**: BIOS、ブートセクタ、`0x7C00`、`55 AA`、リアルモード、`[org]`、`hlt`

## ② 512バイトの壁を越える — [02-stage2.md](02-stage2.md)

**分かったこと**
- 512バイトでは何もできないので、**2段構え** にする。ステージ1はディスクの続きを読み込んでジャンプするだけ
- ディスクの読み込みは `int 0x13`(`ah=0x42`)。「どこから・何セクタ・メモリのどこへ」を DAP という表に書いて渡す
- セクタの位置は先頭からの通し番号(LBA)で指定する
- BIOS は起動したディスクの番号を `dl` で渡してくれる

**キーワード**: ステージ1 / ステージ2、`int 0x13`、DAP、LBA、セクタ

## ③ 32ビットモードと C 言語 — [03-protected-mode.md](03-protected-mode.md)

**分かったこと**
- 4GB のメモリと C 言語を使うため、**プロテクトモード** に切り替える。代わりに BIOS は使えなくなる
- 切り替えの手順: A20 を有効に → 割り込みを止める → GDT を教える(`lgdt`)→ CR0 の PE ビットを 1 に → ファージャンプ
- **GDT** は「メモリをどう使うか」を CPU に教える表
- OS を作るときの C には、標準ライブラリも `main` を呼んでくれる人もいない。`entry.asm` が `.bss` を0で埋めてから `kmain()` を呼ぶ
- リンカスクリプトで「カーネルを `0x8000` 番地から並べる」と指示する
- 画面には VRAM(`0xB8000`)に直接書く。1文字は「文字 + 色」の2バイト。`volatile` で書き込みを最適化で消させない

**キーワード**: プロテクトモード、GDT、CR0、ファージャンプ、A20、`-ffreestanding`、リンカスクリプト、`.bss`、VRAM、`volatile`

## ④ 割り込み — [04-interrupts.md](04-interrupts.md)

**分かったこと**
- 「いつ来るか分からないもの」を待つ方法は、ポーリング(何度も見に行く)と **割り込み**(来たら知らせてもらう)がある。割り込みなら待つ間は CPU を休ませられる
- 装置の信号(IRQ)は **PIC** に集まり、PIC が CPU に割り込み番号として伝える。CPU の例外(0〜31)と重ならないよう、IRQ 0〜15 を 32〜47 にずらす(リマップ)
- **IDT** は「割り込み番号 → 飛び先」の表。入り口(`isr.asm`)でレジスタを全部保存してから C を呼び、`iret` で戻る
- 処理が終わったら PIC に **EOI** を送る。忘れると次の割り込みが来ない
- **割り込みの中は短く**: キーボードは文字をリングバッファに入れるだけで、表示はメインのループでする(ネットワークの受信も同じ形にする予定)
- タイマー(PIT)を 100Hz にして、OS の時計にした
- CPU の例外は赤字で表示して止まる。`EIP` と `nm -n build/kernel.elf` を見比べると、どこで起きたか分かる

**キーワード**: 割り込み、IRQ、PIC、リマップ、マスク、EOI、IDT、ISR、`iret`、例外、PIT、スキャンコード、リングバッファ、`volatile`

## ⑤ メモリ管理 — [05-memory.md](05-memory.md)

**分かったこと**
- パケットや TCP の接続のように、**いつ・いくつ要るか分からないもの** のために「借りて、返す」しくみが要る
- 3段構えになっている
  1. **メモリの地図(E820)**: どこが使ってよいかは BIOS しか知らない。プロテクトモードに入る前にステージ2で聞いておく
  2. **ページの管理(pmm)**: メモリを 4KB のページに区切り、1ページを1ビットで記録する(ビットマップ)。番地を12ビット右にずらすとページ番号
  3. **ヒープ(kmalloc / kfree)**: ページを「見出し + 中身」の区画に切り分けて貸す。返されたら隣の空き区画とくっつけて、断片化を防ぐ
- 安全な側に倒す設計: ビットマップは「全部使用中」から始め、使ってよい所だけ空ける。1MB より下(カーネル、スタック、BIOS)は貸さない
- 番地 0 は絶対に貸さないので、「失敗」の印に使える(`malloc` の `NULL` と同じ考え方)
- `kfree` に番地しか渡さなくても大きさが分かるのは、16バイト手前に見出しがあるから
- gcc はループを勝手に `memset` 呼び出しに置き換えることがある。`memset` 自身はループで書かず、`rep stosb` を使う

**キーワード**: E820、ページ、ビットマップ、ファーストフィット、分割、結合、断片化、見出し、二重解放

## ⑥ ネットワークカード — [06-network-card.md](06-network-card.md)

**分かったこと**
- PCI の装置は番号が決まっていないので、起動したら **総当たりで聞いて回る**。`0xCF8` に「どの装置の何バイト目か」を書き、`0xCFC` を読む。vendor が `0xFFFF` なら誰もいない
- 装置の窓口(BAR0)や IRQ は BIOS が決めて設定空間に書いておいてくれる。OS は読むだけ
- カードとのやりとりは2種類: 命令や状態は **レジスタ(I/O ポート)**、フレームの中身は **DMA**(カードが CPU を通さずにメモリへ直接読み書き)
- DMA には PCI の **バスマスタ** の許可が要る。外すと何も受信できない(実際に試して確かめた)
- 受信は 8KB の **リングバッファ**。見出し(状態 + 長さ)付きで順に書かれ、読んだら CAPR で場所を返す。WRAP ビットで輪の終わりをはみ出して書かせると、読む側が楽
- 送信は4つの箱を順番に使う。番地を TSAD に、長さを TSD に書くと送信が始まり、終わると OWN ビットが立つ
- カードに渡すメモリは「ひと続き」が必要なので、kmalloc ではなく pmm_alloc でページ単位で借りた
- Ethernet の見出しは「宛先 MAC・送り主 MAC・種類」の14バイト。60バイト未満は 0 で埋めて送る
- ARP は「この IP の人の MAC は?」を全員(ブロードキャスト)に聞くしくみ
- ネットワークの数は **ビッグエンディアン**(上位バイトが先)。x86 とは逆なので並べ替えて読む
- 割り込みは ISR を読んで書き戻す(write 1 to clear)だけ。読み出しはメインのループ。④ のキーボードと同じ形

**キーワード**: PCI、設定空間、vendor / device、BAR、バスマスタ、DMA、レジスタ、MAC アドレス、リングバッファ、CAPR、descriptor、Ethernet フレーム、ブロードキャスト、ARP、ビッグエンディアン、write 1 to clear

## ⑦ Ethernet / ARP / IP / ICMP — [07-network-stack.md](07-network-stack.md)

**分かったこと**
- 通信は **層** に分かれている。受信は下から上へ見出しを外し、送信は上から下へ見出しを足す。各層は自分の見出しだけを読む
- IP アドレスで指定しても、線の上の宛先は MAC アドレス。**ARP** で調べて表に覚えておく。問い合わせに答えないと、外からの ping は始まりもしない
- IP パケットの宛先は最終目的地のまま。同じネットワークなら本人、違えばゲートウェイ(**ネクストホップ**)の MAC へ渡す。判断には **ネットマスク** を使う
- 届いたものは信用しない。**見出しの長さを信じて読むとバッファの外を読む** ので、届いた大きさと矛盾しないか先に確かめる
- **チェックサム** は「2バイトずつ足す → あふれた分を足し戻す → 反転」。受け取った側が欄ごと計算すると 0 になる
- Ethernet は 60 バイトまで 0 で埋められるので、中身の長さは IP 見出しの「全体の長さ」から求める
- ping の正体は ICMP の Echo。種類を 8 から 0 に変えてチェックサムを計算し直し、そのまま返す
- QEMU の user モードは外からの ping を通さない。**tap** でつなぎ、**ネットワーク名前空間**(`unshare`)の中なら sudo なしで作れる
- BIOS のディスク読み込みは 64KB の境目をまたげない。セグメントを進めながら分けて読む

**キーワード**: 層、見出し、ARP テーブル、ネクストホップ、ネットマスク、ゲートウェイ、チェックサム、TTL、断片(フラグメント)、MTU、ICMP Echo、tap、network namespace、セグメント:オフセット

## ⑧ TCP — [08-tcp.md](08-tcp.md)

**分かったこと**
- IP は届かなくても順番が変わっても何もしない。TCP は **データの1バイトごとに番号(seq)を振り**、「次はこの番号が欲しい」(ack)と返し合って確実に届ける
- **3ウェイハンドシェイク** は、お互いの最初の番号を伝えて確認し合うためのもの。SYN と FIN も番号を1つ使う
- **ACK が来るまで送信バッファから消さない** から送り直せる。待ち時間は再送のたびに2倍にする(指数バックオフ)。同じ ACK が3回続いたら待たずに送り直す(高速再送)
- 番号は 4GB で 0 に戻るので、大小は **引き算して符号付きで見る**
- **ウィンドウ** で受信バッファの空きを伝える(フロー制御)。0 のときは「空いた」の知らせが失われると止まるので、1バイト送って様子を見る(ウィンドウプローブ)
- TCP は **方向ごとに別々に閉じる**(ハーフクローズ)ので切断は4回。先に閉じた側には **TIME_WAIT** が残る
- RST はつながりを即座に切るので、番号がぴったりのときだけ信じる
- OS にプロセスがなくても、**待たずにすぐ戻る関数をループから呼び続ければ** 複数のつながりを同時に扱える
- 行儀の悪い相手を試すには、テスト側で相手役を作る。本物の Linux との通信だけでは、ウィンドウプローブのバグは見つからなかった

**キーワード**: シーケンス番号、累積確認応答、3ウェイハンドシェイク、ISN、MSS、疑似ヘッダー、再送、RTO、指数バックオフ、高速再送、フロー制御、ウィンドウ、ウィンドウプローブ、ハーフクローズ、TIME_WAIT、状態遷移、RST、輻輳制御(作っていない)、hostfwd

## ⑨ HTTP サーバー — [09-http.md](09-http.md)

**分かったこと**
- HTTP は **人が読めるテキストの手紙**。リクエスト行・ヘッダー・空行・本文の順で、行は CRLF で区切る
- TCP はただのバイトの列なので、区切りは HTTP 側で決める。**見出しの終わりは空行、本文の終わりは Content-Length**
- **keep-alive** は、応答の終わりが Content-Length で分かるからこそできる。HTTP/1.1 は続けるのが標準、1.0 は閉じるのが標準
- **HTTP/1.1 では Host が必須**。1つの IP で複数のサイトを動かすとき、どのサイト宛てかは手紙の中の Host でしか分からない(⑩ で使う)
- 相手から来た文字列は信用しない。HTML に入れるならエスケープする(XSS)。解釈が分かれる形は断る(リクエストスマグリング)
- 黙った相手に行を占領させないよう、状態ごとに **時間切れ** を決める。見出しの持ち時間は最初の1バイトから数える(Slowloris)
- 受け取ってくれない相手には FIN も届かないので、**RST で打ち切る** しかない
- 送信バッファより大きい応答は、入るだけ入れて続きを覚えておき、空いたらまた入れる

**キーワード**: リクエスト行、ステータス行、ヘッダー、CRLF、Content-Length、Content-Type、ステータスコード(2xx / 4xx / 5xx)、GET / HEAD、keep-alive、パイプライン、Host ヘッダー、XSS、エスケープ、リクエストスマグリング、Slowloris、タイムアウト、NAT、X-Forwarded-For

## ⑩ バーチャルホスト — [10-vhost.md](10-vhost.md)

**分かったこと**
- TCP の段階では「どの IP のどのポートに来たか」しか分からない。名前は DNS で番号に変えたときに捨てられるので、**ブラウザが Host ヘッダーに書いて届ける**
- 名前ベースのバーチャルホストは、**整える → 一覧の上から比べる → なければ先頭のサイト** の順で選ぶ。Apache の `<VirtualHost>` も同じ
- 比べる前に整える: 大文字と小文字を区別しない、ポート番号を外す、最後の `.` を外す。ポートでは選ばない(転送の前と後で番号が違うのが普通)
- 比べ方は **ぴったり一致**。「含む」「で終わる」のような緩い比べ方は、他人の名前で開かれる穴になる
- 一覧の先頭が **既定のサイト**。本物のサイトを先頭に置くと、IP アドレスで来た相手や知らない名前にもそのサイトが答える。先頭には受け皿を置く
- サイトを選ぶのは **リクエストごと**。1つの keep-alive のつながりで、別々のサイトに頼める
- HTTPS では Host を読む前に証明書を選ぶ必要があるので、TLS のあいさつで名前を送る(SNI)
- `.localhost` で終わる名前は「この PC 自身」と決まっていて、hosts ファイルなしでブラウザから試せる

**キーワード**: バーチャルホスト、名前ベース / IP ベース、ServerName、ServerAlias、DocumentRoot、既定のサイト(default vhost)、正規化、完全一致、DNS、`.localhost`(RFC 6761)、SNI、421 Misdirected Request、Punycode

## ⑪ 本物の Apache と見比べる — [11-apache.md](11-apache.md)

**分かったこと**
- `vhost.c` の `vhosts[]` は、Apache の設定ファイルの `<VirtualHost>` の並びと1対1で対応する。先頭が既定のサイトなのも同じ
- 同じ 30 通りのリクエストのうち 26 件で同じ答え。整え方(小文字、ポート、最後の点)、ぴったり一致、既定のサイト、keep-alive の中でのサイト選びは Apache と同じに作れていた
- 違ったのは「形のおかしい Host」と「URL に名前が入ったリクエスト」。Apache は **形がおかしければサイトを選ぶ前に 400 で断る**。hobby-os は既定のサイトに回していた
- RFC 9112 では、Host の値が正しい形でなければ 400 にしなければならない。URL に名前があれば Host より URL を使う
- 入り口で厳しく断るのは、部品ごとに Host の読み方がずれると攻撃に使われるため(Host ヘッダー攻撃、リクエストスマグリング)
- Apache では、サイトが決まる前に断ったリクエストも、**先頭のサイト** の設定とログで扱われる
- 1024 以上のポートで、ログの置き場所も自分のフォルダにすれば、Apache は sudo なしで動かせる。Ubuntu 標準では `sites-available` に1サイト1ファイルで置き、`a2ensite`、`apache2ctl configtest`、`systemctl reload` の順で反映する

**キーワード**: httpd.conf、`<VirtualHost>`、`Listen`、`LoadModule`、SSI(mod_include)、`LogFormat` の `%v`、`HttpProtocolOptions Strict`、absolute-form、RFC 9112、`.invalid`(RFC 6761)、sites-available / sites-enabled、a2ensite、apache2ctl configtest / -S、systemctl reload(graceful)

## 全体を通して分かったこと

- **「誰がやってくれていたか」を自分でやる**: 普段の C では OS がやってくれていたこと(`.bss` を0にする、`malloc`、画面への表示)を、全部自分で用意する必要がある
- **BIOS に頼めるのはリアルモードの間だけ**: ディスクの読み込みもメモリの地図も、32ビットに切り替える前に済ませておく
- **番地の取り決めが大事**: `0x1000`(メモリの地図)、`0x7C00`(ステージ1)、`0x7E00`(ステージ2)、`0x8000`(カーネル)、`0x90000`(スタック)、`0xB8000`(画面)。どこに何を置くかを決めて、ぶつからないようにする
- **作ったら QEMU で確かめる**: 起動時のテスト(`heap_self_test`)や確認用の表示(`last sector loaded OK.`、`mem`)を入れておくと、壊れたときにすぐ分かる

```
           │ BIOS の作業場所、画面など   │ ← 0xB8000 が文字の画面
0x00100000 ├─────────────────────────────┤ 1MB
           │ pmm が貸し出す範囲          │ ← kmalloc のヒープもここから借りる
           │        …                    │
           └─────────────────────────────┘
```
